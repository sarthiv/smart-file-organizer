SMART FILE ORGANIZER
MODULE 5 — ACTUAL FILE ORGANIZATION & CONFLICT HANDLING
CONCEPT NOTES

1. MODULE GOAL
This module changes the organizer from only calculating a destination path to safely moving files.
It also handles duplicate filenames automatically.

Main flow:
Scanner -> Classifier -> Organizer -> Preview -> Safety Check -> Move File
                                            -> Conflict Handler

2. shutil
Python's built-in shutil module provides high-level operations for files and folders.
We use:
    shutil.move(source, destination)

It physically moves a file from its source location to the destination.

3. mkdir(exist_ok=True)
We create the category folder when required:
    destination_folder.mkdir(exist_ok=True)

exist_ok=True means:
- If the folder does not exist, create it.
- If it already exists, do not raise an error.

4. PATH EXISTENCE CHECK
Path.exists() checks whether a file or folder exists.

Example:
    if destination_file.exists():
        ...

This is important for preventing accidental overwriting.

5. INITIAL CONFLICT PROTECTION
The first version of organize_file raised FileExistsError when a destination file already existed.

Purpose:
- Protect the existing file.
- Prevent accidental overwrite.
- Make duplicate detection explicit.

6. NESTED FOLDER SAFETY
A problem was discovered when a file was already inside its correct category folder.

Example:
    Documents/notes.txt

Without a safety check, the organizer could calculate:
    Documents/Documents/notes.txt

The fix checks:
    if file.parent.name.lower() == category.lower():
        return str(file)

This means a file already in the correct category is not moved again.

7. CASE-INSENSITIVE COMPARISON
.lower() converts text to lowercase.

Example:
    "Documents".lower() == "documents".lower()

This allows the category comparison to work even when capitalization differs.

8. CONFLICT HANDLER
File:
    app/services/conflict_handler.py

Function:
    get_unique_destination(destination: Path)

Purpose:
If a destination filename already exists, generate a safe alternative.

Example:
    resume.pdf
    resume (1).pdf
    resume (2).pdf
    resume (3).pdf

9. Path.stem AND Path.suffix
For:
    resume.pdf

Path.stem:
    resume

Path.suffix:
    .pdf

We combine them with a counter:
    f"{destination.stem} ({counter}){destination.suffix}"

Result:
    resume (1).pdf

10. while LOOP
The conflict handler uses a while loop to keep checking filenames.

Logic:
    If destination is free -> use it.
    If destination exists -> try (1).
    If (1) exists -> try (2).
    Continue until a free name is found.

11. FINAL ORGANIZER BEHAVIOR
The final organize_file logic:
- Convert source string into Path.
- Check whether the file is already in the correct category.
- Create the category folder if necessary.
- Calculate the destination.
- Ask conflict_handler for a unique destination.
- Move the file using shutil.move().
- Return the final destination path.

14. WHY CONFLICT HANDLING IS IMPORTANT
A real file organizer can encounter files with the same name.
Overwriting an existing file could cause data loss.

Automatic conflict handling protects user data by preserving both files.

15. INTERVIEW / VIVA QUESTIONS

Q1. What is shutil?
Answer: A Python standard-library module used for high-level file and directory operations.

Q2. How do you move a file in Python?
Answer:
    shutil.move(source, destination)

Q3. What does Path.exists() do?
Answer: It checks whether a file or directory exists.

Q4. Why is exist_ok=True used with mkdir()?
Answer: It prevents an error when the directory already exists.

Q5. What is Path.stem?
Answer: The filename without its extension.

Q6. What is Path.suffix?
Answer: The file extension, including the dot.

Q7. Why should duplicate files not be overwritten?
Answer: To prevent accidental data loss.

Q8. Why do we use a while loop in the conflict handler?
Answer: To keep generating and checking new filenames until an unused name is found.

Q9. Why do we check whether a file is already inside its category folder?
Answer: To prevent unnecessary moves such as Documents/Documents/file.txt.

Q10. What is modular programming?
Answer: Dividing a program into separate modules/functions with focused responsibilities.

16. CURRENT ARCHITECTURE

scanner.py
    -> scans files and collects metadata

classifier.py
    -> determines category from extension

organizer.py
    -> determines destination and performs safe movement

conflict_handler.py
    -> generates unique names for duplicates

This separation makes the project easier to maintain, test, and extend.
